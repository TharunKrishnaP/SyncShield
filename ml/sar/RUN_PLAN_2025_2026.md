## 3. Builder changes required before Phase 1 (small, testable, committed)

1. **Token per scene + retry (critical)** — `get_cdse_token()` is currently
   called once before the loop, but a token dies after 10 min while one scene
   takes longer than that to download+calibrate → guaranteed 401 mid-run.
   Fix: mint a token per scene (cheap OIDC POST), and retry the download up
   to 3× with a fresh token on 401/403/429/5xx with exponential backoff.
2. **Integrity check** — verify written bytes == `Content-Length`; re-fetch if
   short (silent truncation would poison calibration).
3. **`--keep-safe` flag** — delete the 4.5 GB unzipped SAFE after calibration
   by default (F: can hold them, but 24 × 4.5 = 108 GB).
4. **`--jobs N` (≤ 4, per CDSE limit)** for the download-only phase;
   calibration stays sequential (CPU-bound).
5. **Chipping v2 — faster *and* more correct**:
   - **scene-level Otsu** on a decimated VH read (~1/8 scale) instead of
     per-chip Otsu on 256×256 (per-chip thresholding is statistically noisy
     and biases labels per chip);
   - **targeted extraction**: read only windows whose decimated water mask is
     non-empty → ~10–25× less I/O than scanning every window;
   - **`--max-chips-per-scene N`** (deterministic, seeded per scene) to bound
     the dataset for CPU training;
   - per-scene progress + incremental `chips_meta.json` (crash-safe resume).
   - Labels stay canonical `{-1, 0, 1}` = {no-data, not-water, water}; weak
     Otsu on VH σ⁰ dB; `--gsw-tiff` permanent-water subtraction unchanged.
   - New unit tests: scene-level threshold == decimated-scan threshold on a
     fixture; retry-on-401 with a mocked token endpoint; chip cap honoured.
     (Synthetic arrays are fine in *unit tests*; the no-synthetic guard
     applies to the dataset itself.)
6. **`ml/sar/select_scenes.py`** — deterministic selector:
   `manifest.json` + `district_coverage.csv` → `scene_plan.json`
   (`scene, state, district, role=train|holdout, bbox, acquired, flood_prone`).
   Also emit a committed human-readable summary through
   `ml/evidence/make_panindia_summary.py`-style output.

## 4. Scene selection policy (honest, documented)

- **Train pool** — 2025-06-01 … 2025-10-31 (monsoon/flood season) scenes whose
  footprint contains a **flood-prone district HQ**: 2–3 per basin across
  Brahmaputra (AS), Ganga–Kosi (BR), Ganga–Ghaghara (UP), Ganga delta (WB),
  Godavari (MH), Krishna (AP/KA), Mahanadi (OD), Cauvery (TN), Malabar (KL),
  Narmada (MP/GJ).
- **Val pool (temporal holdout)** — the most recent **2026-08/2026-09**
  scenes, 4–6, distinct orbits/districts. The model never trains on them.
- **Honest caveat (must appear in docs/evidence)**: an Otsu threshold on VH
  σ⁰ dB detects **water**, not specifically **flood**; permanent-water
  subtraction via JRC GSW (`--gsw-tiff`) narrows it to non-permanent water.
  The weak-label methodology matches Sen1Floods11's own WeakLabeled pool.

## 6. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Token expires mid-download (certain with today's code) | per-scene token + retry (§3.1) |
| Monthly quota exceeded → 1 MB/s | cap transfer ≈ 40 GB; check CDSE dashboard after Phase 1 |
| USB drive unplugged / letter changes (F: → E:) | re-verify drive before each stage; write all paths from one root variable; keep manifest copy on C: |
| Training reads many small chip files from USB (slow random I/O) | copy the final chips set to C: for training if it fits (~6–8 GB), else train from F: (I/O is not the bottleneck vs CPU) |
| Weak labels noisy → low IoU | report honestly; compare vs baseline; offer GSW subtraction upgrade |
| Val/train scene overlap (leak) | selector marks roles; test asserts disjoint scene IDs |
| Long CPU training | cap chips/scene; Colab T4 option |
| Crash mid-stage | per-scene logs, idempotent steps (already-calibrated tifs/zips skipped) |

## 8. Exact command sequence (copy-paste)

```powershell
# 0. credentials + root (per shell session; not persisted)
$env:CDSE_USER = "<your cdse email>"; $env:CDSE_PASS = "<password>"
$R = "F:\floodml\india_2025_2026"; New-Item -ItemType Directory -Force -Path $R | Out-Null
Copy-Item ml\data\india_2025_2026\manifest.json $R\ -Force

# 1. scene plan (deterministic; --per-basin 2 --holdout 6)
python ml\sar\select_scenes.py --manifest $R\manifest.json --out $R\scene_plan.json --per-basin 2 --holdout 6

# 2. one scene at a time: download (fresh token) + calibrate VV/VH

python ml\sar\build_india_2025_2026.py download-dem --out $R\dem --bbox lon0,lat0,lon1,lat1

# 4. chips, two passes (temporal holdout): train pool then val pool
python ml\sar\build_india_2025_2026.py chips --out $R\chips --sar-dir $R\sar --dem-dir $R\dem --val-frac 0 --size 256 --stride 256 --max-chips-per-scene 600
python ml\sar\build_india_2025_2026.py chips --out $R\chips --sar-dir $R\sar_holdout --dem-dir $R\dem --val-frac 1 --size 256 --stride 256 --max-chips-per-scene 600

# 5. train (artifacts separate from the live model)
python ml\sar\train_unet.py --data-dir $R\chips --size 256 --epochs 35 --pos-weight 8 --grad-clip 1.0 --out ml\artifacts\sar_unet_2025_2026

# 6. swap live (no code change) + restart + verify
#   .env: ML_SAR_DIR=ml/artifacts/sar_unet_2025_2026

Invoke-RestMethod http://localhost:8000/api/ai/models | ConvertTo-Json -Depth 4
```
