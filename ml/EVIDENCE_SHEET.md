## D — Incident text classifier (trained, live in backend)

- **Model**: TF-IDF (1–2 grams, sublinear) → LinearSVC, Platt-scaled
  (`CalibratedClassifierCV`, balanced class weights) · 11 classes · trained with
  `ml/text/train_svc.py` on a laptop CPU.
- **Corpus** (`ml/data/text_corpus.jsonl`): **56,978 real rows** —
  **48,997 train / 7,981 test**, built by `ml/text/build_real_corpus.py` from
  **real human-annotated crisis text only**:
  - **HumAID set1** (43,409 human-annotated tweets across 13 disasters, official
    train/dev/test splits) as the primary source — includes
    `srilanka_floods_2017` and `maryland_floods_2018`;
  - **CrisisNLP** (paid-worker CrowdFlower + volunteer annotations, incl. the
    2014 India/Pakistan floods) as the secondary source;
  - **6 live datalake rows** (CITIZEN_REPORT + NDMA_SACHET, test-only).
  - Labels: HumAID/CrisisNLP humanitarian labels → 11 FDR action categories via
    the documented keyword-refined mapping (`_refine_fdr` + `_TOKEN_RULES`) in
    `build_real_corpus.py`. Non-incident classes (sympathy, not_humanitarian,
    …) are dropped; no template-generated text exists anywhere.
- **Split**: **event-disjoint** — entire real disasters are held out of
  training: `srilanka_floods_2017`, `maryland_floods_2018`, Cyclone Pam,
  Typhoon Hagupit, Hurricane Odile + live datalake rows. Test rows come only
  from disasters **never seen in training** (no event leakage).

Top cross-event confusions: EVACUATION_NEEDED→OTHER ×139 · RELIEF_SHELTER_FULL→
OTHER ×33 · OTHER→EVACUATION_NEEDED ×30 · FLOODED_ROAD→OTHER ×25. The rare classes
the 43K-tweet weak supervision cannot recover on unseen disasters (FLOODED_ROAD,
BRIDGE_COLLAPSE, COMMUNICATION_DOWN, HOSPITAL_ACCESS_BLOCKED) are honestly
reported here and rescued in production by the documented hybrid rule layer
(`backend/app/ml/text_classifier.py`: evidence gates + rule override +
hospital/roof-strand signals) — the deployed model + rules together decide.

```

                         Patna, road to the district hospital is flooded"}
→ category TRAPPED_RESIDENTS · confidence 0.7928 · method "ml"
  top3: TRAPPED_RESIDENTS 0.7928 · OTHER 0.1273 · FLOODED_ROAD 0.0591
  rule_category: HOSPITAL_ACCESS_BLOCKED (rule engine fired; the model's pick
  is ≥ the 0.75 rule-override floor, so per the documented decision order the
  model decides — TRAPPED_RESIDENTS)
```

Note: the earlier v1-template model returned HOSPITAL_ACCESS_BLOCKED 0.9859 for
this text; the **real-corpus v2** model returns TRAPPED_RESIDENTS 0.79 and the
rule engine reports HOSPITAL_ACCESS_BLOCKED. Whichever wins, the hybrid layer
keeps both signals visible (`rule_category` in the response), so a reviewer can
see the disagreement. Report the category honestly.

Seed incidents (orchestrator `_seed_incidents`, 18 scenario sentences): the v2
real-corpus model triages them as **TRAPPED_RESIDENTS ×3 · EVACUATION_NEEDED ×3
(one via hybrid-rules rescue) · FLOODED_ROAD ×1 · OTHER ×11**. The OTHER-heavy
majority is honest out-of-distribution behaviour: the model was trained on real
human-annotated tweets, and terse scenario sentences ("Farakka barrage release
raising water…", "Sabarmati overflow… relief material dispatched") carry none of
the lexical signals its training disasters used. High-signal seeds (rooftop /
families trapped, "need evacuation", "street flooding") classify correctly at
high confidence. This is the documented trade-off of training only on real data
(FLOODED_ROAD cross-event F1 0.00) — the rule layer rescues only when the model
is uncertain (<0.75).

## C — Sentinel-1 SAR flood U-Net (pipeline live; full-IoU training on Colab)

- **Data**: Sen1Floods11 (cc-by-4.0) from the **canonical public GCS bucket**
  `sen1floods11` (the old HF mirror `harshinde/sen1floods` now 401s anonymous
  downloads, so the downloader fetches the exact files it needs directly from
  GCS — no auth, no ~35 GB tar). Real-run scope: the dataset's **single India
  event** (2016 Assam, **535 chips**) — `download_sen1floods11.py --events India`
  fetches `S1Hand` 2-band VV/VH imagery + water labels, ~0.9 GB on disk,
  arranged in the dataset's own split:
  - `WeakLabeled/` — **467 chips** with auto Otsu labels (metadata `train_chip`)
  - `HandLabeled/` — **68 chips** with human QC labels (metadata `val_chip`)
- **Labels**: canonical Sen1Floods11 encoding — `1 = water`, `0 = not water`,
  `-1 = no data` (masked out of the loss). Weak labels are the Otsu water mask
  (`{0,1}`), hand labels are human QC (`{-1,0,1}`).
- **Model**: U-Net, encoder resnet18 (imagenet-pretrained), in=2, out=1,
  weighted BCE-with-logits + Adam, LR 3e-4, grad-clip 1.0, pos-weight 8.0
  (run #1 at plain BCE/lr-1e-3 diverged to all-NaN weights — see note below).
- **Training**: `ml/sar/train_colab.ipynb` on a free T4
  (`train_unet.py --data-dir ml/data/sen1floods11`) → val IoU/Dice reported in
  `ml/artifacts/sar_unet/meta.json`. Split = the **dataset's own geographic
  split** (`Sen1Floods11(partition=...)`: train reads WeakLabeled, val reads
  HandLabeled; chip-id sets are disjoint by construction), so the reported val
  IoU is on hand-QC chips/labels the model never saw — no leak. *Bandwidth
  note: if the HandLabeled pool is not downloaded (e.g. a data-cap-constrained
  quick local run), the loader falls back to a deterministic 85/15 chip-id
  hash split over the real chips present — still held-out, still real data,
  and the meta.json `note` records which split was used.*
- **Real run #1 (2026-09-24, T4) — DIVERGED, artifact rejected**: the first
  real-data attempt (plain BCE, lr 1e-3, no clipping) produced
  `val_iou 0.0417` and a state dict that was ~99.96 % NaN (training blew up;
  some Sen1Floods11 tiles contain NaN/Inf pixels and the sparse ~1 % water
  class collapsed to all-background). The NaN checkpoint was **not** deployed
  into the demo. Run #2 uses the hardened recipe above (non-finite pixel
  sanitising in the loader, LR 3e-4, grad-clip 1.0, pos-weight 8.0) and the
  trainer now fails **soft** (diverged.log sidecar, existing good artifacts
  preserved) instead of overwriting them with a NaN model.
- **Local certification — LIVE (this repo, CPU, real data)**:
  `train_unet.py --data-dir ml/data/sen1floods11 --size 128 --epochs 35
  --batch-size 8 --lr 3e-4 --grad-clip 1.0 --pos-weight 8.0` — trained on the
  **real** India chips from the public GCS bucket with the **canonical
  dataset split**: **467 WeakLabeled train / 68 HandLabeled val** (human-QC
  labels the model never saw; no chip-id leakage). Measured val IoU **0.2758** /
  Dice **0.3861** (best epoch state saved; all weights finite, no
  `diverged.log`). The
  demo scene is itself a real Sentinel-1 tile (`scene_india_assam.tif`,
  ~10 m/px, Assam, from the HandLabeled pool — reproducible with
  `ml/sar/mk_real_scene.py`, so no synthetic scene generator exists) —
  produced live via `POST /api/ai/sar/ingest` (`data_source ML_SAR_UNET`).
  No synthetic data anywhere.
- **Integration**: `POST /api/ai/sar/ingest` (scene upload) → extent records
  (zone_id, flood_area_km2, water_depth_avg, flood_status, polygons,
  data_source "ML_SAR_UNET") → datalake → orchestrator feeds the 0.35
  satellite weight in real-time mode. Fail-soft: 501 + training pointer until
  a model exists.
